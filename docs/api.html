API Reference

OctoTasks exposes a JSON REST API at /api/tasks. All request and response bodies use Content-Type: application/json.

This API is intentionally simple for training purposes. It uses an in-memory store — data resets when the server restarts.

Task Object

FieldTypeDescription
idintegerAuto-assigned unique identifier
titlestringShort title of the task (required)
descriptionstringOptional longer description
statusstringtodo | in-progress | done
createdAtISO 8601 stringCreation timestamp

Endpoints

GET /api/tasks

Returns all tasks. Optionally filter by status.

Query paramTypeDescription
statusstringOne of todo, in-progress, done
 
GET /api/tasks?status=todo
HTTP 200
[
  {
    "id": 4,
    "title": "Write API documentation",
    "description": "Document all REST endpoints.",
    "status": "todo",
    "createdAt": "2024-01-18T00:00:00.000Z"
  }
]

GET /api/tasks/:id

Returns a single task by its numeric ID.

GET /api/tasks/1
HTTP 200
{
  "id": 1,
  "title": "Set up GitHub repository",
  ...
}

Returns 404 if the task is not found.

POST /api/tasks

Creates a new task. New tasks default to status: "todo".

Body fieldRequiredDescription
title✅ yesTask title (max 120 chars)
descriptionnoLonger description (max 255 chars)
 
POST /api/tasks
{ "title": "Review PR #42", "description": "Check the new search feature" }

HTTP 201
{
  "id": 6,
  "title": "Review PR #42",
  "description": "Check the new search feature",
  "status": "todo",
  "createdAt": "2024-06-01T10:00:00.000Z"
}

Returns 400 when title is missing or blank.

PATCH /api/tasks/:id

Updates one or more fields of an existing task.

Body fieldDescription
titleNew title
descriptionNew description
statustodo | in-progress | done
 
PATCH /api/tasks/3
{ "status": "done" }

HTTP 200
{ "id": 3, "status": "done", ... }

Returns 400 for an invalid status value, 404 if not found.

DELETE /api/tasks/:id

Permanently deletes a task.

DELETE /api/tasks/3

HTTP 204 No Content

Returns 404 if the task does not exist.

Health Check

GET /health

HTTP 200
{ "status": "ok", "app": "OctoTasks", "timestamp": "2024-06-01T10:00:00.000Z" }
Training tip: Use the health check endpoint in the CI workflow to confirm the server started successfully before running integration tests.
